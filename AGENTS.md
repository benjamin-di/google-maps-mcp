# Working on google-maps-mcp

Run `make bootstrap`, then `make check` (ruff, the format check, the lock-consistency check and
pytest). After a dependency change run `make lock`: `requirements-runtime.lock` must equal
`uv export` of `uv.lock`, because the image installs exactly that file.

Tests never reach Google: the vendored library runs against recorded responses
(`tests/conftest.py`, `tests/fixtures/README.md`). `tests/test_safety.py` is the boundary: a new
host, a network import outside `google.py`, using more of the library (reviews, contacts,
websites, login cookies), or a card view that loads or connects beyond its CSP is a deliberate
change there, never a side effect.

`src/maps_mcp/vendor/gmaps` is generated by `scripts/vendor-gmaps.sh`; never edit it here.
Parsing fixes and new Google fields go to gmaps-scraper first (README "How it works").

Probing Google live from a development machine is fine in small amounts: a handful of
requests, paced, never in a loop. Re-record fixtures only with `scripts/capture-fixtures`,
which scrubs per-request tokens, photo URLs and non-Google links; review the diff before
committing it.

Keep the code, comments, docs and fixtures free of personal details (names, addresses,
accounts, hosts): this repository is public.
